# DEF CON Demo Scripts

Three scripts to run live on the Kali box (`10.3.2.28`) alongside the browser
tab showing `https://demo-dashboard.defcon.ztlp/`, for proving the demo is
real and not a static mockup.

## `mint-user-and-show-policy.sh`

Mints a real, signed USER identity in the ZTLP namespace for "crash"
(role=admin), mints a second standard-role user ("alice") for contrast,
queries both back from NS live to prove they're real records, then shows
the gateway's policy engine granting/denying access to an admin-only
service based purely on each user's role — same policy engine, same code
path, different outcome driven by data (the role field in each signed NS
record), not special-cased per-user logic.

```bash
./mint-user-and-show-policy.sh
```

## `prove-not-docker-port-forwarding.sh`

Proves the browser's HTTPS traffic reaches the backend through a
ZTLP-managed virtual IP + Noise tunnel, not Docker `-p` port publishing.

```bash
./prove-not-docker-port-forwarding.sh
```

Walks through: Docker's actual published port list (443 is never in it) →
the real host listener on :443 (owned by the `ztlp` agent process, bound to
a `127.100.x.x` virtual IP) → live DNS resolution through the agent's own
resolver allocating that VIP → confirming the VIP isn't a real, externally
reachable interface address → a live curl showing the TLS handshake
connecting to that VIP.

Interactive by default (pauses between sections) — pipe `yes ""` through it
for a non-interactive run.

## `live-traffic-demo.sh`

Proves the system does live cryptographic work on every hit, not just
serves a cached page. Fires a burst of real HTTPS requests through the full
path, then shows the exact delta in the gateway's live Prometheus counters
(handshakes, bytes in/out) and pulls fresh entries from the dashboard's own
audit-log API — timestamps generated by the burst just sent.

```bash
./live-traffic-demo.sh            # one burst of 10 requests
./live-traffic-demo.sh 25         # burst of 25 requests
./live-traffic-demo.sh 10 loop    # repeat every 8s until Ctrl-C
```

`loop` mode is meant to run on a second screen/terminal next to the browser
tab during a talk — the counters tick up in the terminal while the
browser's own 5-second auto-refresh shows the same audit log growing live.

## Prerequisites

Both assume the full defcon stack is already up (`docker compose up -d` in
`~/defcon`) and the ZTLP agent is running (`ztlp agent status`). The
mint-user script additionally requires `ZTLP_GATEWAY_POLICIES` to include
a `role:admin:<service>` rule (already set for the `admin-panel` service
name in `~/defcon/docker-compose.yml`). All three were verified working
end-to-end against the live Kali stack on 2026-08-06/07 — see
`docs/defcon-2026-kali-buildout-notes.md` for the underlying fixes that
made this possible (rustls provider panic, gateway routing, NS identity
persistence, USER/GROUP record truncation, role:/group: policy parsing).
